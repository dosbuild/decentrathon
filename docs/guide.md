# Руководство dalel

## Запустить локально

Нужен Python 3.10 или новее.

```sh
python -m venv .venv
# macOS / Linux
. .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install .
locqa serve
```

Откроется локальное рабочее пространство. Выберите **Open files**, загрузите исходный и целевой ARB. Для узбекского укажите `uz`, для казахского — `kk`. Через **Reference files & reports** можно добавить контекст других языков, глоссарий и сохранённые находки.

Интерфейс входит в установленный пакет; отдельная сборка JavaScript не нужна. Данные и журнал сохраняются локально. `locqa serve --no-browser --port 4189 --data-dir data/private/workspaces` задаёт порт и каталог явно. Сервер принимает подключения только с localhost.

## Проверить через CLI

```sh
locqa check --source intl_ru.arb --target intl_kk.arb --glossary glossary.csv --out report.json
locqa check --source intl_ru.arb --target intl_uz.arb --glossary glossary.csv --out uz/report.json
```

Рядом с каждым JSON создаётся соответствующий HTML-отчёт. Он открывается без сервера, содержит поиск и фильтры. Глоссарий хранит `ru`, `kk`, `en` и примечания; колонка `uz` задаёт узбекские соответствия.

По умолчанию работают локальные проверки и совместимый сохранённый анализ. Покрытие каждого запуска указано явно: детерминированный проход не выдаётся за полную языковую вычитку.

Для разрешённого модельного прохода задайте настройки из `.env.example`: `OPENAI_API_KEY`, `LOCQA_BASE_URL`, `LOCQA_MODEL` и положительный `LOCQA_BUDGET_USD`. Нулевой бюджет отключает запросы.

```sh
locqa check --source intl_ru.arb --target intl_kk.arb --glossary glossary.csv \
  --profile full --corrected intl_kk_fixed.arb --out report.json
```

`--ref` добавляет языковые версии, `--context` — JSON с контекстом игры. Модель готовая: промпты и контекст направляют её работу, обучения внутри проекта нет. Новые запросы учитываются отдельно от воспроизведения сохранённых ответов.

## От находки к утверждённому переводу

1. Запустите **Check all translations**, откройте находку и контекст.
2. Перенесите предложение через **Use as draft** или отредактируйте текст.
3. Выберите **Approve revision** либо **Request changes** для показанной версии.
4. В **Release** проверьте выбранный ARB и подготовьте связанные файлы.

Изменение строки снимает её прежнее утверждение. Подтверждение находки и принятие перевода независимы. Устаревшая вкладка не может перезаписать новую работу. Резервная копия хранит черновики, но не создаёт человеческих решений.

Для чтения всей подборки вне редактора:

```sh
locqa prepare-approval --data-dir workspaces --editorial editorial.json --out approval
locqa import-approval --data-dir workspaces --snapshot approval/approval.json --response response.json
```

Пакет показывает номера, исходник, прежний перевод, предложение, причину и контекст. Хеш фиксирует снимок. Ответ содержит `snapshot_sha256`, номера в `approve` или строку `all`, подпись `reviewer` и явное `attest_human: true`. Импорт отклоняет изменённые версии. Модельное заключение хранится отдельно; статус носителя не выводится из факта принятия текста.

Сохранённый полный анализ можно открыть через `locqa open-workspace`. `locqa prepare-review --bundle … --out …` подготавливает очередь черновиков. `locqa review-html` и `locqa apply-review` поддерживают автономный экран разметки. Все команды доступны через `locqa --help`.

## Структура остаётся под защитой

Парсер сохраняет произвольные ключи, метаданные и историю повторяющихся членов ARB. Проверки учитывают плейсхолдеры, ICU, теги, защищённые символы и края строк. Каждая находка использует ровно девять полей контракта; дополнительные редакторские сведения хранятся отдельно.

JSON, HTML, глоссарий, список изменений и исправленный ARB формируются из одного выбранного состояния. Flutter проверяет буквальный файл и адаптированную копию раздельно. Для SDK задайте `LOCQA_FLUTTER` или добавьте Flutter в `PATH`; проект использует закреплённую версию 3.47.9. Без SDK результат остаётся `not_run`.

Некорректные исходные имена Flutter требуют явной миграции; таблица имён входит в адаптированный пакет. Успех адаптированной копии не означает успешную компиляцию исходных ключей. Сообщения, которым нужен неизвестный аргумент или изменение кода игры, остаются открытыми зависимостями.

## Дополнительные возможности

- **Узбекский:** тот же CLI, интерфейс, ревью и экспорт; собственные правила языка и латинской орфографии.
- **Казахская латиница:** `locqa transliterate --source intl_kk_fixed.arb --out intl_kk_Latn.arb`. Версионный профиль `kk-latn-2018-decree637` и отчёт `latin_length_report.json` сохраняют таблицу преобразования, длины и риски роста. Для Flutter нужен базовый `kk` как fallback. Латинская версия не наследует утверждение кириллической.
- **Проверка PR:** `.github/workflows/arb.yml` сравнивает изменённые ARB одним инструментом из базовой ревизии. Пути берутся из `l10n.yaml` или переменных `LOCQA_SOURCE_ARB` и `LOCQA_TARGET_ARBS`. Модельные запросы не выполняются.
- **Аффиксы:** безопасные шаблоны получают предложение без суффикса у динамического значения. В остальных случаях требуется контекст или код; окончания неизвестного имени не угадываются.

Профиль латиницы относится к редакции 2018 года и не заявляет актуальность всех последующих редакций. Проверка длины не заменяет проверку игровых шрифтов и реального размера кнопок.

## Проверить и собрать проект

```sh
python -m pip install ".[test]" build "setuptools==80.9.0"
python -m pytest -q
python -m build --no-isolation
```

Тесты проверяют ARB и ICU, отчёты, глоссарий, привязку решений к версии, экспорт и локальный HTTP-сервис. Для проверки JavaScript-клиента нужен Node.js. Контрактные тесты не измеряют качество перевода на скрытой выборке. CI запускает тесты и сборку на Linux и Windows.

Для компиляции своих исправленных ARB нужен отдельный Flutter SDK. Успешные Python-тесты сами по себе не подтверждают `flutter gen-l10n` для ваших файлов.
